## Identified acceptance failure vs proposed remedy

- **Observed:** new canonical image booted and ordinary chat, structured native `tool_calls` and SSE tool cycle passed; the **separate performance benchmark** returned an object that failed the migration `PASS` acceptance predicate. The original caller discarded the samples, thus exact root cause remains **UNVERIFIED**, even with successful Native Tools.
- **Prior client:** three sequential `stream=true` ChatCompletion prompts with `max_tokens=64`, seed 1234, temperature 0, `stream_options.include_usage=true`; it included natural-language `/no_think` but did **not** explicitly set `chat_template_kwargs.enable_thinking=false`. The server's reasoning parser may deliver `reasoning` instead of `reasoning_content` in some API versions; both forms are now accounted for. Neither is proof of the first failure's exact cause.
- **Revised CANONICAL-only recipe** `recipes/qwen38-27b.runtime.json` adds `benchmark.version=p2-27b-native-tools-canonical-benchmark-v2`, `max_tokens=128`, `requests=3`, `concurrency=1`, `seed=1234`, `temperature=0`, `stream=true`, `stream_options.include_usage=true`, `chat_template_kwargs.enable_thinking=false`. The extra output budget reduces 64-token truncation risk, but DOES NOT guarantee result PASS. **v1 64-token historical measurements must not be compared numerically as if the same workload**.
- **Acceptance still strict:** all three response streams must reach SSE `[DONE]`, contain generated content or reasoning, report nonzero actual `completion_tokens` from the server and measurable first output token; positive real observed E2E token throughput is required. Do **NOT** fabricate token counts, infer speed from random tokens or mark missing usage as PASS.
- **Diagnostic:** for each request, report whether usage, content, reasoning, TTFT, terminal `finish_reason` and tokens were observed; include a bounded reason code. Persist private immutable `benchmark-observed-<newSHA>.json` *BEFORE acceptance* so a rejection can be diagnosed. Do not record generated text or prompts.
- **Safety:** do not change original / Flash / trial variant images or checkpoint file contents; do not install an alternate container or enable MTP/FP8 KV, alter large-context, prefix caching or speculative decoding during this correctness-focused migration. Those are **optional future performance experiments** after verified baseline operation.
